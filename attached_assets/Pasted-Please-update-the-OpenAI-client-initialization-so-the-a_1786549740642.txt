Please update the OpenAI client initialization so the app works correctly in BOTH Replit development and GCP production.

Current problem:
- GCP production has a real OPENAI_API_KEY.
- Replit development uses AI_INTEGRATIONS_OPENAI_API_KEY + AI_INTEGRATIONS_OPENAI_BASE_URL.
- Several files, including server/ai-service.ts, are hard-coded to use only the AI_INTEGRATIONS_* variables.
- In GCP, that causes SOAP generation and potentially other AI features to fail because the Replit modelfarm proxy/base URL does not exist there.

Required behavior:
1. In production, ALWAYS prefer process.env.OPENAI_API_KEY.
2. If OPENAI_API_KEY is present, do NOT pass AI_INTEGRATIONS_OPENAI_BASE_URL at all. Let the OpenAI SDK use the normal OpenAI endpoint.
3. Only fall back to AI_INTEGRATIONS_OPENAI_API_KEY and AI_INTEGRATIONS_OPENAI_BASE_URL when OPENAI_API_KEY is not present, for Replit development.
4. Do not remove Replit development support.
5. Do not change SOAP prompts, note logic, clinical extraction logic, models, or any unrelated functionality.

Use this pattern anywhere a new OpenAI client is created:

const apiKey =
  process.env.OPENAI_API_KEY ||
  process.env.AI_INTEGRATIONS_OPENAI_API_KEY;

const baseURL = process.env.OPENAI_API_KEY
  ? undefined
  : process.env.AI_INTEGRATIONS_OPENAI_BASE_URL;

const openai = new OpenAI({
  apiKey,
  ...(baseURL ? { baseURL } : {}),
});
